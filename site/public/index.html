Run your own PaaS.

Get started

Bootstrap a control-plane VPS, connect a server plan, and deploy your first app. If your team already runs Selfrun, download the CLI and jump to step 2.

Requirements

  • OpenSSH on your workstation
  • Cloud API token from your VPS provider
  • Domain with DNS access

  1. 1. Bootstrap your control plane

    The control plane runs your private cloud—it hosts the web console and API, executes deployments, and tracks your servers, domains, and secrets.

    • Download CLI
    • Build from source
    • Setup guide
    ~ 
    $ selfrun seed
✓ Guided wizard provisions your VPS & prints the /setup URL

  2. 2. Sign in and create a server plan

    A server plan maps a cloud provider account, region, and machine size to a reusable name like small. Connect multiple provider accounts and define as many plans as you need, then add your first plan under Plans in the web console.

    • Providers & plans guide
    ~ 
    $ selfrun instance add prod cloud.example.com
✓ Connected to https://cloud.example.com
$ selfrun login
✓ Signed in — add a provider & plan under Plans in the console

  3. 3. Deploy an app

    Apps are configured and deployed from the CLI. Selfrun detects your services, provisions a dedicated server from your plan, sets up HTTPS, and prints the live URL.

    • CLI & config reference
    ~/my-app 
    $ selfrun init
✓ Wrote selfrun.yml (web, api)
$ selfrun deploy --build-mode source
✓ Deployed → https://my-app.apps.example.com

How it works

Host the control plane once on a small VPS. Every app environment and Git branch preview runs on its own server in your cloud account, managed from the web console, CLI, or CI.

Workloads stay isolated per environment, repositories stay free of cloud SKUs and provider keys, and your cloud provider bills you directly with zero markup.

Control plane & server plans

Connect multiple cloud accounts across providers and define named server plans so repositories never hardcode cloud credentials or machine types.
