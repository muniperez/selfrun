Run your own PaaS

Connect a cloud account and deploy web apps, APIs, background workers, and databases from the CLI or CI. Selfrun provisions the servers, configures domains and HTTPS, and leaves billing with your provider.

Get started

Bootstrap a control-plane VPS, connect the CLI, and deploy your first app. If your team already runs Selfrun, download the CLI and jump to step 2.

Requirements

  • OpenSSH on your workstation
  • A cloud provider account and API token
  • A domain where you can add DNS records

  1. 1. Bootstrap your control plane

    The control plane runs your private cloud—it hosts the web console and API, executes deployments, and tracks your servers, domains, and secrets.

    Download the CLI (or build from source) and run the interactive setup:

    selfrun seed

    Control-plane setup guide

  2. 2. Sign in and create a server plan

    A server plan maps a cloud provider account, region, and machine size to a name like small. You can connect multiple provider accounts and define as many plans as you need.

    Sign in from your terminal, then add a provider account and plan under Plans in the web console:

    selfrun instance add prod cloud.example.com
selfrun login

    Providers & plans guide

  3. 3. Deploy an app

    Apps are configured and deployed from the CLI. Selfrun detects your services, provisions a dedicated server using your chosen plan, sets up HTTPS, and prints the live URL.

    In your project repository, generate selfrun.yml and deploy:

    selfrun init
selfrun deploy --build-mode source

    CLI & config reference

How it works

Host the control plane once on a small VPS. Every app environment runs on a dedicated server in your cloud account, managed from the web console or CLI.

Control plane & server plans

One VPS runs your dashboard, API, secrets, and deployment engine. Connect multiple cloud accounts across providers and define named plans (region and server size) so repositories never hardcode cloud credentials or machine types.

Apps, environments & domains

Deploy public web apps, private internal APIs, and background workers together or redeploy one service at a time. Give staging, production, and Git branch previews separate servers with automatic HTTPS and custom domains.

Databases, volumes & secrets

Run a database alongside an app or provision dedicated database servers with scheduled encrypted backups and restore. Attach expandable persistent volumes for files and inject scoped secrets into services at runtime.

CLI, CI & coding agents

Trigger deployments from your terminal, CI pipelines, or a connected Git repository. Because deploys, health checks, and runtime logs all run through the CLI, coding agents can deploy changes, inspect failures, and verify live URLs directly.
