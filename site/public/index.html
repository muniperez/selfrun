Coding VMs and deployments

Run a coding agent on a VM

Start a VM in Dev Environments and open T3 Code in your browser. Use its terminal to clone a repo and run tests. The VM image determines which agents are installed. Open an app preview from the dashboard. When you stop the primary VM, its disk keeps your files and T3 sessions.

First workspace guide ↗

Deploy Docker services

Run minicloud init in an app repository and select the services to deploy. minicloud deploy builds the images and rolls the services out to an app server. Public services get HTTPS URLs. Set a custom domain, check deployment progress, and read service logs in the dashboard.

What runs on each server

Install the MiniCloud dashboard, API, and worker on one VPS. The worker provisions separate coding VMs and app servers in your Hetzner, DigitalOcean, or Vultr account. App visitors reach public services over HTTPS. You connect to a coding VM through the workspace gateway.

Set up MiniCloud

If you have a MiniCloud instance, start by connecting the CLI. If you need an instance, install a test server.

Connect to an instance

Get the dashboard hostname and the sourceRevision from your operator or your instance’s /api/instance response. Install the matching CLI with Git and the .NET 10 SDK. If you built the CLI during server setup, start with minicloud instance add. Complete minicloud login in your browser.

instance_sha='REPLACE_WITH_INSTANCE_SOURCE_SHA'
curl -fsSL https://raw.githubusercontent.com/muniventures/minicloud/main/install.sh |
  MINICLOUD_INSTALL_MODE=source MINICLOUD_VERSION="$instance_sha" \
  MINICLOUD_INSTALL_DIR="$HOME/.local/bin" sh

export PATH="$HOME/.local/bin:$PATH"
minicloud instance add personal cloud.example.com
minicloud login

Open a coding workspace

Dev Environments require a configured workspace gateway, an approved VM image, and a plan. If you're the operator, enable Dev Environments and prepare a workspace image first.

  1. Go to Dev Environments → Create dev environment. Name it, choose a size, location, and storage, then review the estimate and create it. This starts the primary VM.
  2. When the VM is Running, select Connect to T3 → Open T3. In T3, open Settings → Providers and sign in to your coding provider. Open a project or clone a repository in the terminal.
  3. Stop the VM when you're done. Files on the primary volume are retained, and storage charges continue while the VM is stopped.

Deploy an app

From your app's Git checkout, run minicloud init. Select or create the app, pick a plan if prompted, and choose the service directories. The CLI saves your choices in minicloud.yml. Start Docker with Buildx for the default local build.

minicloud init
minicloud deploy

Use minicloud deploy --build-mode source for a server-side build, or add --environment staging to select an existing staging environment. Open the service URL printed by the CLI. In the dashboard, use Deployments to check the result and Apps → your app → Domains to add a custom hostname.

Install a test server

The server installer builds from source. You need Git, Python 3.11 or newer, the .NET 10 SDK, OpenSSH, a VPS provider account, and DNS access. The commands use a Unix shell and a DigitalOcean account. A signed production installer is pending.

  1. Build the server archive and matching CLI. Start with a clean checkout. Save the SHA-256 printed by the packaging command. 
    git clone https://github.com/muniventures/minicloud.git
cd minicloud
umask 077
seed_dir="$PWD/.local/artifacts/local-seed"
mkdir -p "$seed_dir/reports"

python3 -B scripts/self-hosting/local_source.py package \
  --version 0.0.1-local.1 --output "$seed_dir/source.tar.gz"

dotnet publish modules/cli/Minicloud.Cli.csproj -c Release \
  --artifacts-path "$seed_dir/cli-build" --output "$seed_dir/cli" \
  -p:SourceRevisionId="$(git rev-parse HEAD)"
minicloud() { dotnet "$seed_dir/cli/Minicloud.Cli.dll" "$@"; }
minicloud seed new-id
  2. Configure the server. Save this example as $seed_dir/seed-config.json with mode 0600. Fill in your seed ID, provider account, region, size, and domains. Keep the same seed ID for retries. Put the provider token in $seed_dir/provider-token with mode 0600. Use an existing SSH private key. If it has a passphrase, unlock it with ssh-add and add --use-ssh-agent to the seed commands. 
    {
  "schemaVersion": 1,
  "seedId": "REPLACE_WITH_SEED_ID",
  "provider": "digitalocean",
  "providerAccount": "DigitalOcean account REPLACE_WITH_ACCOUNT_UUID",
  "region": "nyc3",
  "size": "s-2vcpu-2gb",
  "domain": "cloud.example.com",
  "appDomain": "apps.example.com",
  "serverVersion": "server-v0.0.1-local.1",
  "architecture": "linux/amd64",
  "initialCreationIntent": "one-authorized-creator-no-unresolved-create"
}
  3. Review the plan and create the VPS. Set the archive hash, key path, and token file path before running the commands. Check the account, size, region, and cost in the plan. Substitute its approval digest before running apply. Use --new-seed only for the initial creation. If the create result is uncertain, check the provider console before retrying. 
    source_sha256='REPLACE_WITH_ARCHIVE_SHA256'
ssh_key="$HOME/.ssh/id_ed25519"
credential_file="$seed_dir/provider-token"

seed_local() {
  minicloud seed "$@" --config "$seed_dir/seed-config.json" \
    --report "$seed_dir/reports/seed-report.json" --ssh-key "$ssh_key" \
    --local-source "$seed_dir/source.tar.gz" --source-sha256 "$source_sha256"
}

seed_local plan --credential-file "$credential_file" --new-seed
seed_local apply --credential-file "$credential_file" --new-seed \
  --approve REVIEWED_CREATION_DIGEST
  4. Verify the server and finish installation. Check the VPS in the provider console and obtain its SSH host key fingerprint there. Add a target object with serverId, ipv4, and hostFingerprint to the config. Remove initialCreationIntent, then review and approve a new plan without --new-seed. 
    seed_local plan --credential-file "$credential_file"
seed_local apply --credential-file "$credential_file" \
  --approve REVIEWED_CONTINUATION_DIGEST
  5. Set up DNS and claim the instance. Point cloud.example.com and api.cloud.example.com at the control-plane VPS using the report's DNS instructions. Once both respond over HTTPS, export the recovery files and setup token. Open https://cloud.example.com/setup, enter the token, and create your operator account. Sign in normally. Keep the recovery files encrypted and off the VPS. 
    minicloud seed export --config "$seed_dir/seed-config.json" \
  --report "$seed_dir/reports/seed-report.json" --ssh-key "$ssh_key" \
  --recovery-dir "$seed_dir/private-recovery" --setup-token
  6. Add a provider and a plan. In the dashboard, open Plans, connect a provider account, and create a plan with a region and server size for your apps.
